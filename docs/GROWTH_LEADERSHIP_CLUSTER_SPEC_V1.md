# JoyLab Growth · Leadership Cluster Spec V1

Status: Candidate → Gold after GC-G01~G03 + Pillar validation
Updated: 2026-09-12

## Purpose

JoyLab의 세 번째 Pillar인 `성장·리더십`을 감성적인 리더십 조언이 아니라 **측정 가능한 팀 운영 시스템**으로 구축한다.

핵심 질문은 하나다.

> 사람을 더 몰아붙이지 않고도, 어떤 운영 구조가 더 나은 성과와 성장을 반복 가능하게 만드는가?

## Research Map

**Goal → Measurement → Feedback → Recognition → Fairness → Operating System**

초기 Gold Case는 다음 3편으로 시작한다.

1. GC-G01 Performance System — 결과 KPI보다 Leading Indicator를 먼저 설계하는 법
2. GC-G02 Feedback System — 평가가 아니라 행동 변화를 만드는 피드백 구조
3. GC-G03 Recognition System — 인정·보상이 성과를 강화하려면 무엇이 필요한가

3편 확보 후 `/guides/growth-leadership` Pillar V2를 구현한다.

## JoyLab Growth Leadership Lens

**Outcome → Driver → Behavior → Feedback → Recognition → Fairness → Learning → Action**

### OUTCOME
무엇을 좋은 성과로 볼지 결과 기준을 명확히 한다.

### DRIVER
결과를 만드는 선행지표와 통제 가능한 변수를 찾는다.

### BEHAVIOR
숫자 아래 실제 행동을 관찰 가능한 수준으로 정의한다.

### FEEDBACK
행동을 반복·수정할 수 있도록 빠르고 구체적인 피드백 루프를 설계한다.

### RECOGNITION
잘한 행동과 성장을 조직이 보이게 만들어 반복 가능성을 높인다.

### FAIRNESS
기준·기회·판정 과정이 일관되고 설명 가능한지 점검한다.

### LEARNING
실수와 실패가 재발하지 않도록 학습 단위와 재시험·재실행 구조를 남긴다.

### ACTION
다음 주기에서 무엇을 유지·수정·중단할지 결정한다.

## Editorial Rules

- 추상적인 리더십 미사여구보다 **운영 가능한 구조**를 우선한다.
- 결과 KPI와 선행지표를 분리한다.
- 개인 문제를 구조 문제와 혼동하지 않는다.
- 피드백은 성격 평가가 아니라 관찰 가능한 행동과 다음 행동을 중심으로 쓴다.
- 인정·보상은 단순 인기투표가 아니라 명시된 기준과 증거에 연결한다.
- 공정성은 모두를 똑같이 대하는 것이 아니라 **같은 기준을 설명 가능하게 적용하는 것**으로 본다.
- 모든 글은 마지막에 `Scenario / Action` 또는 다음 실행 조건을 남긴다.
