## 0. Operating principle

AI는 상담사의 판단을 대신하는 권한자가 아니라 **판단 보조 도구**로 사용한다.

- 반복 업무는 줄인다.
- 고객 권리·금액·보상·예외·법률 판단은 최신 SOP와 전산 조회, 승인 절차를 우선한다.
- 원문에 없는 사실은 만들지 않는다.
- 불확실하면 `[확인 필요]`로 남긴다.
- 중요한 결정은 근거와 승인 주체를 기록한다.

## 1. AI 사용 전 5단 Gate

### Minimize
AI에 꼭 필요한 정보만 넣는다.

### Mask
이름·전화번호·계좌/카드번호·상세주소 등 식별 가능 정보는 회사 기준에 맞춰 비식별화한다.

### Ground
금액·기간·보상·약관·법률처럼 틀리면 위험한 내용은 SOP·공식 전산 조회 범위 안에서만 답하게 한다.

### Approve
고객 권리·보상·예외 처리·법률 판단에 영향을 주는 결과는 담당자 또는 승인권자가 확인한다.

### Record
어떤 근거를 확인했고 누가 승인했는지 남긴다.

## 2. 상담 프롬프트 기본형

```text
역할: 고객센터 상담사의 판단을 보조하는 AI
목표: 고객 상황을 사실 중심으로 정리하고, 고객에게 안내할 문장 초안을 만든다.

규칙:
1. 입력된 사실만 사용한다.
2. 원문에 없는 사실은 추가하지 않는다.
3. 금액·기간·보상·약관·법률은 제공된 SOP나 전산 조회값이 없으면 [확인 필요]로 표시한다.
4. 고객 개인정보는 식별 가능한 형태로 재출력하지 않는다.
5. 고객에게 확정적으로 말하기 전에 사람이 확인해야 할 항목을 마지막에 분리한다.

출력:
- 사실 요약
- 고객 요청
- 확인해야 할 규정/전산
- 안내 문장 초안
- [확인 필요] 항목
```

## 3. CRM 3 Lines

1. 인입분류 및 핵심사유
2. 안내 팩트 및 규정
3. 최종 조치 및 합의 결과

### CRM prompt

```text
아래 상담 메모를 CRM 3줄로 정리해줘.

1줄: 인입분류 + 핵심사유
2줄: 실제 안내한 팩트/규정
3줄: 최종 조치 + 고객과 합의된 결과

규칙:
- 원문에 없는 사실을 추가하지 말 것
- 추측하지 말 것
- 불확실한 내용은 [확인 필요] 표시
- 감정 평가 대신 관찰 가능한 사실만 기록
```

## 4. QA Coaching — SBI + Alternative

### Situation
어떤 상황이었는지 구체적으로 적는다.

### Behavior
평가어 대신 실제 발화·행동을 적는다.

### Impact
고객 이해·해결 흐름·품질 기준에 미친 영향을 설명한다.

### Alternative
다음 상담에서 바로 사용할 대체 질문/대체 문장을 한두 개 제시한다.

### Coaching prompt

```text
아래 상담 사례를 SBI + Alternative 구조로 코칭 초안으로 만들어줘.

규칙:
- 상담사의 의도나 성격을 추측하지 말 것
- 실제 발화와 행동만 근거로 삼을 것
- 잘된 점과 수정할 행동을 분리할 것
- 대체 스크립트는 한두 개만 제시할 것
- 마지막에 재점검 시점과 관찰할 행동을 남길 것
```

## 5. Leader Weekly AX Routine

**Measure → Observe → Coach → Re-run → Learn → Update Standard**

- Measure: 품질·재작업·후처리·오류 신호 확인
- Observe: 사람보다 먼저 업무·행동·도구에서 원인 확인
- Coach: 취약 행동 TOP3 중 우선순위 지정
- Re-run: 재실행 일정 지정
- Learn: 반복 실패/성공을 사례·체크리스트·프롬프트로 축적
- Update Standard: 검증된 방법만 팀 표준과 SOP 보조자료에 반영

## 7. Stop Conditions

다음 상황에서는 AI 초안을 그대로 사용하지 않는다.

- 개인정보 식별 가능성이 남아 있음
- 최신 SOP/전산 조회가 없음
- 금액·보상·약관·법률을 확정해야 함
- 예외 승인 또는 권한 판단이 필요함
- AI가 원문에 없는 사실을 생성함

## 8. Success Metrics

- 평균 후처리 시간
- CRM 수정률
- 누락 필드 비율
- 재문의 원인이 된 기록 오류
- 같은 취약 행동의 반복 여부
- 코칭 후 재실행 성공 여부
- 리더 재작성 비율

도입 전후 동일 기준으로 비교한다.
