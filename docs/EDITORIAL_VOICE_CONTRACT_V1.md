# JoyLab Editorial Voice Contract V1.0

Status: ACTIVE (new Research article writing and material rewrites)
Effective: 2026-10-21
Scope: JoyLab Research `src/data/articles/*.md`, editorial drafts handed to the Publishing OS
Owner: JoyLab
Principle: **문장은 전문 칼럼처럼, 근거는 리서치 보고서처럼.**

## 1. 목적과 권한

JoyLab의 공통 목소리를 **자연스럽고 깊이 있는 전문 칼럼체**로 유지하되 글의 질문과 유형에 따라 구조를 달리한다.

이 문서는 **문체·편집 품질 계약**이다. 새 점수, 자동 발행 권한, GitHub Actions workflow 또는 SEO 순위 보장을 만들지 않는다. 기존 `docs/ARTICLE_ARCHITECTURE_V1_1.md`가 정한 5가지 콘텐츠 유형과 Common Trust Layer, `docs/CONTENT_DATE_CONTRACT_V1.md`, 사실 검증·릴리스 계약이 우선한다. 이 계약과 충돌한다면 데이터 정확성, 독자 효용, 출처, 안전성, 기존 실행 게이트를 우선하고 충돌 이유를 기록한다.

기존 공개 글을 일괄 수정하지 않는다. **신규 작성과 사용자가 요청한 실질적 윤문·리라이트부터 기본 적용**한다. 단순 오탈자 수정에는 문체 전환을 강제하지 않는다.

## 2. 모든 유형에 적용하는 7가지 기본 규칙

1. **사람이 설명하는 문장:** 주제를 이해한 필자가 독자에게 맥락, 의미, 한계를 설명하듯 쓴다. 정의·숫자·조건은 명료하게 전달한다.
2. **질문과 답:** 제목이 약속한 질문에 본문이 직접 답해야 한다. 서사형 도입도 첫 2~3문단 안에서 쟁점과 핵심 방향을 제시한다. 억지로 `핵심 답:` 문구를 매번 넣지 않는다.
3. **관찰과 해석의 분리:** 출처에서 확인한 사실·작성자 자체 보고·JoyLab의 해석·전망·가상 예시를 문장 안에서 구분한다. 직접 검증하지 않은 것은 검증했다고 쓰지 않는다.
4. **유기적인 흐름:** 사례/질문 → 필요한 근거 → 해석/반론 → 조건부 판단·실행으로 이어가되, 글마다 같은 H2와 고정 표현을 반복하지 않는다.
5. **데이터의 보존:** 숫자, 날짜, 단위, 분모, 비교 기간, 산식, 공식 출처, 불확실성을 윤문 과정에서 삭제하거나 바꾸지 않는다. 비교가 중요하면 표·차트를 유지한다.
6. **과장 배제:** `무조건`, `혁명`, `필승`, `충격`, `완벽한` 같은 자극적 단정, 검증되지 않은 효율 개선/수익률, 과도한 질문형 제목, 장식용 영어를 피한다.
7. **고유 가치:** 같은 정보를 말만 부드럽게 바꾼 요약을 새 리서치로 제시하지 않는다. 원문과 다른 JoyLab의 판단 조건, 비교, 재현 가능한 절차, 체크리스트 또는 분석 중 하나 이상을 제공한다.

## 3. 콘텐츠 유형별 기본 문체

`contentType`은 기존 `src/content.config.ts`의 다섯 유형을 그대로 사용한다.

| 유형 | 기본 목소리 | 끝까지 유지할 정보 |
| --- | --- | --- |
| `investment-analysis` | 데이터 중심 전문 분석, 문단으로 해석을 연결 | 주가/실적 시점, 출처, EPS·현금흐름·밸류에이션의 산식·가정, 반대 시나리오. 문학적 서사보다 정확성 우선 |
| `concept-explainer` | 쉽고 정교한 개념 해설 | 명확한 정의, 작동 원리, 개념 차이, 오해와 적용 범위 |
| `comparison` | 동일 조건을 제시하는 비교 분석 | 대상/버전/기간, 선정된 비교 축, 1개의 실용적 비교표, 누락·미확인 항목, 상황별 선택 조건 |
| `industry-trend` | 사례와 산업 맥락을 연결하는 전문 칼럼 | 변화의 근거, 영향을 받는 주체, 전파 경로, 병목, 반대 논리, 관찰 지표 |
| `practical-playbook` | 현장의 문제를 설명하는 사례 중심 실무 칼럼 | 대상·입력·담당·승인·예외·검증, 측정 가능한 KPI/실행 절차. 실행을 돕는 표·템플릿은 허용 |

제목에 `AX`, `AI`, `주식`이 있다는 이유만으로 문체를 선택하지 않는다. **독자가 원하는 최종 산출물**(이해, 판단, 비교, 실행)을 우선한다.

## 4. SEO·AEO와 자연스러운 글의 접점

- **Title/H1:** 명확한 검색 주제 + 글의 고유 관점. 과장·클릭베이트 금지.
- **도입:** 검색 의도에 빠르게 답하면서도 사례·갈등·질문을 통해 읽을 이유를 제공한다. `핵심 답` 카드 강제 금지.
- **H2:** 각각 독립적으로 이해 가능한 자연스러운 소제목. H2 개수 고정 금지; 검색어를 어색하게 반복하지 않는다.
- **근거:** 각 주요 숫자와 주장 가까이에 출처 또는 검증 범위를 제공한다. 기준일, 발표일, 관측 시점을 혼용하지 않는다.
- **검색 구조:** 정확한 `seoTitle`, `description`, canonical, 내부 연결, 필요한 경우 FAQ를 유지한다. FAQ는 실제 독자가 묻는 질문이 있을 때만 사용하며 리치 결과 노출을 보장하지 않는다.
- **원본성:** 내용 추가 없이 문체만 바꾼 글은 새로운 글이 아닌 기존 URL의 수정으로 처리한다. `publishedAt` 유지, 실질적 수정일만 `updatedAt`에 기록한다.
- **출처/Disclosure:** Common Trust Layer와 `humanReviewed`의 실제 검토 증거 규칙을 우선한다.

## 5. 문장 운영 원칙

**권장**
- 짧은 문장과 긴 문장을 섞어 독자의 호흡을 조절한다.
- 기술 용어는 처음 등장할 때 필요한 범위만 풀어 설명한다.
- 숫자 다음에는 그 숫자가 **뜻하는 것과 뜻하지 않는 것**을 구분한다.
- 논지의 긴장과 반론을 실제 근거에 연결한다.
- 결론은 본문에서 도출한 조건부 관점이나 독자가 확인할 다음 행동으로 끝낸다.

**피함**
- `Research Brief / Key Takeaways / JoyLab Insight / 최종 판단 / 실행 5단계` 같은 반복적인 제목을 글마다 기계적으로 붙이는 것.
- 두 줄마다 굵은 글씨나 불필요한 번호·표를 넣는 것.
- 외부 발표문을 윤문해 자신만의 독점적 조사처럼 보이게 하는 것.
- 과장된 1인칭 체험담, 허구의 사용 후기, 꾸며 낸 검증 기록.
- 데이터 표가 필요한 투자·비교 글의 표를 전부 산문으로 바꾸는 것.

**문장 예시**
- 딱딱한 형식: `AX의 핵심은 업무 구조 재설계이다. 인간 승인 단계와 KPI 설정이 필요하다.`
- 권장: `AI를 도입했다고 업무가 저절로 바뀌지는 않는다. AI가 작성한 결과를 누가 확인하고, 문제가 생겼을 때 어디서 멈출 수 있는지 정해 놓아야 비로소 조직의 일하는 방식이 달라진다.`

이는 어조의 예시다. 이 문장을 다른 글에 복제하지 않는다.

## 6. 출고 전 에디터 점검 (수동, No New CI)

| 점검 | 통과 질문 |
| --- | --- |
| Voice | 자연스럽고 읽기 쉬운 전문 글인가? 반복적인 AI 템플릿 표현이 없는가? |
| Intent | 제목이 약속한 질문에 첫 부분과 결론이 답하는가? |
| Content Type | 투자/비교/해설/산업/실무에 필요한 표·근거·실행 요소를 보존했는가? |
| Evidence | 수치·기준일·출처·원문/해석/전망/가상 구분이 정확한가? |
| Originality | JoyLab의 근거 있는 독자적 기여가 있는가? |
| SEO·AEO | 자연스러운 제목·소제목, URL·메타데이터·필요한 내부 연결이 맞는가? |
| Publication | 수정 시 기존 `publishedAt`과 URL을 지켰는가? 필수 Build/Release Gate를 통과했는가? |

판정은 `EDITORIAL_READY` / `REVISION_NEEDED` / `FACT_BLOCKED`로 기록할 수 있지만, 이는 **편집 상태**이지 기존 자동화 검사를 대신하거나 PASS를 위조하지 않는다. 원문 검증이 불충분하면 `FACT_BLOCKED`로 두고 출고하지 않는다.

## 7. 최소 운영 경로

1. **Research:** 원문·1차 출처·수치·데이터 시점 확인.
2. **Editorial Rewrite:** 글의 `contentType`에 맞게 자연스러운 칼럼 흐름으로 작성하거나 윤문.
3. **SEO/AEO/Trust:** H1/H2/메타데이터, 원본성, 반대 근거·출처·검증 범위 보존.
4. **Publish:** 기존 `docs/operations/RESEARCH_PUBLISH_FASTLANE_V1.md` 경로로 scoped PR → 필수 Build GREEN → 병합 → Cloudflare/운영 페이지 검증.

이 계약 때문에 신규 GitHub Actions, 예약 실행, 외부 서비스 또는 추가 유료 도구를 도입하지 않는다.

## 8. 적용 범위와 확장

- 신규 JoyLab Research 글: 기본 적용.
- 명시적으로 요청된 리라이트/윤문: 같은 URL을 유지하여 적용.
- 기존 글 전수 개편: 자동으로 수행하지 않음. 독자 효용, 중복, 검색 성과를 보고 대표 글부터 단계적으로 판단.
- 기존 구조 및 보안·배포 게이트: 변경하지 않음.

**핵심:** 브랜드의 목소리는 통일하되, 모든 글을 같은 문장과 단락의 틀에 넣지 않는다.
