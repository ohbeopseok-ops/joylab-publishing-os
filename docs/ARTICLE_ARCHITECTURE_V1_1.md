# JoyLab Article Architecture V1.1

애드센스 승인 준비를 위한 콘텐츠·사이트 운영 기준

개정일: 2026-10-06 | 상태: 운영 명세 | 적용 대상: 신규 글·기존 글 개선·사이트 검수

## 1. 목표와 원칙

최상위 목표는 JoyLab 사이트의 애드센스 승인이다. 이를 위해 독자가 실제로 사용할 수 있는 고유 자료, 근거 있는 분석, 명확한 탐색 구조를 만든다.

모든 글은 Common Trust Layer와 5종 Content Architecture 중 하나를 결합한다. Trust는 통일하고, 본문은 독자의 질문에 맞춰 설계한다.

이 문서는 JoyLab의 내부 운영 기준이다. Google 공식 승인 점수표가 아니며, 내부 PASS와 실제 승인 결과는 별도 기록한다. 현재 계정의 승인·거절 상태는 이 문서에서 확정하지 않는다. 계정의 실제 심사 메시지를 별도 확인해 개선 항목과 연결한다.

### 운영 우선순위

1. 실제 심사 메시지와 공개 사이트 상태 확인
2. 가치가 낮거나 중복된 콘텐츠 정리
3. 독자 효용이 높은 핵심 글 보강
4. 정책·탐색·모바일 사용성 점검
5. 공개 사이트에서 개선 확인 후 재심사

글 수, 분량, 이미지 수를 늘리는 것을 완료 기준으로 삼지 않는다. 신규 발행은 기존 글에 없는 질문을 해결하고 아래 Gate를 통과할 때 진행한다.

## 3. Common Trust Layer

| ID | 요소 | 필수 조건 | 검증할 증거 |
| --- | --- | --- | --- |
| TL-01 | Author | 모든 글 | 실제 작성 주체·분석 관점, 검토 시 실제 검토 기록 |
| TL-02 | Research Date | 시간 민감 글 | 데이터 기준일·출처의 자료 시점 |
| TL-03 | Research Method | 모든 글 | 실제 수행한 조사·비교·계산 방법 |
| TL-04 | Sources | 외부 사실·수치·제도·기술 주장 | 주장과 연결된 출처, 원문 우선 |
| TL-05 | Original Value | 모든 글 | 자체 분석·계산·비교·현장 도구 중 실질적 기여 |
| TL-06 | Counter Evidence | 투자·산업·비교·추천·운영 제안 | 반대 근거·적용 제외 조건·실패 조건 |
| TL-07 | Conclusion | 모든 글 | 본문 근거에서 도출한 조건부 판단·실행 |
| TL-08 | Update Log | 시간 민감·지속 개정 글 | 실제 변경 날짜와 변경 내용 |

### TL-01. 작성과 검토

작성 주체와 관점을 보여준다. 예: “작성: JoyLab Research / 관점: 공시와 현금흐름을 중심으로 기업가치를 분석”. 전문 자격·현장 경험은 확인된 범위만 기재한다.

Human Reviewed는 기본 표시가 아니다. 실제 검토가 완료됐을 때 검토자·검토일·범위를 기록한다. 숫자만 검토했다면 전체 사실·정책 검토까지 완료한 것으로 표시하지 않는다. AI 생성 초안을 사람이 읽었다는 이유만으로 출처 검증 완료를 선언하지 않는다.

### TL-02. 기준일

주식·ETF·금리·환율·실적·정책·AI 모델·가격·기술 사양은 데이터 기준일을 표시한다. 작성일, 데이터 기준일, 실제 수정일을 구분한다. 서로 다른 시점의 데이터를 사용할 때 각 표와 주장에 해당 시점을 적는다.

### TL-03. 조사 방법

사용한 자료와 수행한 작업을 1~3문장으로 설명한다. 직접 테스트하지 않았다면 테스트했다고 쓰지 않는다. 인터뷰·설문·현장 관찰도 실제 수행한 경우에만 기재한다. 계산에는 공식·단위·주요 가정을, 서비스 비교에는 버전·요금제·테스트 조건을 붙인다.

### TL-04. 출처

우선순위: 공시·정부·기업 공식 자료 → 원논문·원통계 → 신뢰도 높은 언론 → 2차 해설. 각 출처가 뒷받침하는 주장을 확인한다. 공식 홈페이지 링크 하나만 넣어 여러 수치를 검증한 것으로 처리하지 않는다.

기본 개념도 정확한 정의의 근거를 연결한다. 순수 현장 경험 글은 외부 출처를 억지로 붙이지 않고 익명화한 관찰·작업 산출물·검증 범위를 근거로 제시할 수 있다. 이 예외는 투자 수치나 외부 정책 주장에는 적용하지 않는다. 확인되지 않은 항목은 미확인으로 표시한다.

### TL-05. 고유 가치

읽은 뒤 독자가 이해·판단·실행 중 무엇을 더 잘할 수 있는지 명확해야 한다. 자체 계산, 동일 조건 비교, 판단 조건, 시나리오, 현장 사례, 사용 가능한 SOP·템플릿 등이 해당한다.

기존 내용을 표로 바꾸거나 “JoyLab 해석” 제목을 붙인 것만으로 통과하지 않는다. 자체 판단은 근거와 추론 과정을 함께 보여준다. 생성 이미지나 상투적 체크리스트만 추가한 글도 보강 대상으로 남긴다.

### TL-06~08. 반대 근거·결론·변경 기록

반대 근거는 본문 주장과 직접 연결한다. “투자에는 위험이 있다” 같은 공통 문구만으로 통과하지 않는다. 설명 글은 흔한 오해나 개념이 적용되지 않는 범위로 대체할 수 있다.

결론은 글의 핵심 질문에 답하고, 근거가 약한 부분은 조건을 붙인다. 업데이트 로그는 실제 사실·수치·판단·도구 변경을 기록한다. 날짜만 새로 바꿔 최신 글처럼 보이게 하지 않는다.

## 4. 유형 선택 규칙

| 독자의 핵심 질문 | contentType |
| --- | --- |
| 이 자산을 어떤 기준으로 판단할 것인가? | investment-analysis |
| 이 개념은 무엇이며 어떻게 작동하는가? | concept-explainer |
| A와 B는 어떻게 다르고 어느 상황에 적합한가? | comparison |
| 산업 구조가 어떻게 변하며 영향은 어디로 전달되는가? | industry-trend |
| 현장의 문제를 어떤 절차로 해결할 것인가? | practical-playbook |

주제 이름보다 글이 답할 질문으로 선택한다. ETF 정의는 설명형, ETF 간 선택은 비교형, 특정 ETF의 가치 판단은 투자형이다. 본문에서 보조 유형의 요소를 사용할 수 있지만 주 유형은 하나로 기록한다.

## 5. Content Architecture 5종

아래 요소는 분석 체크리스트다. 8개의 H2를 그대로 복사하지 않는다. 제목·순서·개수는 글에 맞춰 바꾸고 요소를 통합할 수 있다. 표·그림·본문 중 적합한 방식으로 구현한다.

### 01. Investment Analysis

- 핵심 시장 변화 또는 투자 질문
- 판단 기준일과 데이터 범위
- 핵심 수치·단위·기간·비교 기준
- 확인된 사실과 해석의 구분
- 가치에 영향을 주는 이익·현금흐름·구조 분석
- 반대 논리와 투자 가설이 깨지는 조건
- Bull / Base / Bear의 가정과 관찰 신호
- 투자자가 확인할 지표와 조건

개별 기업은 EPS·현금흐름·밸류에이션 등을 선택한다. ETF는 지수 구성·비용·추적·분배 등을, 금융시장은 유동성·금리·수급 등을 분석한다. 자산 특성에 맞지 않는 기업 지표를 강제하지 않는다. 시나리오 수치에는 가정을 명시하고 확인되지 않은 확률·목표가를 만들어 넣지 않는다.

### 02. Concept Explainer

- 쉬운 정의
- 독자와의 관련성
- 작동 원리
- 실제 사례 또는 명시한 가상 예시
- 비슷한 개념과의 차이
- 이해를 돕는 그림·계산·비유
- 활용 상황과 적용 범위
- 3개 이하의 핵심 메시지

비유가 정확한 정의를 대체하지 않도록 차이를 설명한다. 도식이 필요 없는 단순 개념은 사례만으로 설명해도 된다.

### 03. Comparison

- 비교 대상·버전·기간·목적
- 3~7개의 비교 축과 선정 이유
- 같은 기준으로 만든 비교표
- 항목별 근거 분석
- 수치에 드러나지 않는 차이
- 각 대상의 약점과 미확인 항목
- 독자 상황별 적합성
- 조건별 최종 판단

요금제·기간·통화·부가세·환경 등 차이를 명시한다. 미확인 값을 0으로 처리하거나 사용해보지 않은 서비스를 경험 기반으로 평가하지 않는다.

### 04. Industry & Trend

- 변화 신호
- 단기 변화와 구조 변화의 근거
- 밸류체인과 전달 경로
- 병목과 경쟁 우위
- 직접·간접 수혜 및 실적 반영 조건
- 논리를 깨뜨릴 조건
- 3가지 향후 시나리오
- 다음에 확인할 데이터·정책·실적

산업 성장과 특정 기업의 이익 증가를 구분한다. 매출 증가, 마진, 수주 실행, 자본 투입의 조건을 연결한다.

### 05. Practical Playbook

- 실제 현장 문제와 적용 대상
- 기존 방식의 실패 원인
- 운영 원칙과 적용 범위
- 담당·순서·입력·출력·예외를 포함한 실행 절차
- 실제 사용 가능한 SOP·스크립트·템플릿
- 실패 지점과 대응
- KPI의 정의·산식·측정 기간
- 오늘 실행할 행동과 재점검 시점

측정하지 않은 효과를 실적처럼 쓰지 않는다. 가상 사례는 명시한다. 고객·상담사 사례는 개인정보와 내부 기밀을 제거한다.

## 6. Trust 표시와 Visual Rule

상단은 작성 주체·관점·필요한 기준일만 간결하게 보여준다. 출처는 관련 주장 가까이에 배치하고, 조사 방법·상세 출처·업데이트 이력은 본문 하단에서 제공할 수 있다. 긴 신뢰 블록이 핵심 답변을 밀어내지 않게 한다.

| 유형 | 우선 도구 | 검증 내용 |
| --- | --- | --- |
| 투자형 | 차트·수치표·가치 계산 | 출처·기간·단위·가정 |
| 설명형 | 개념도·흐름도·예시 계산 | 관계·방향·예외 |
| 비교형 | 비교표·매트릭스 | 동일 조건·누락·미확인 값 |
| 산업형 | 밸류체인·산업 지도 | 영향 경로·수혜 조건 |
| 실무형 | SOP·체크리스트·절차도 | 실제 실행 가능성 |

모든 글에 동일한 Visual Research 블록을 넣지 않는다. 이미지는 이해나 근거에 기여할 때 추가한다. 생성 이미지를 실제 제품 화면·시험 결과·통계의 증거로 사용하지 않는다. 그림·표에는 설명과 출처를 붙이고 모바일 가독성을 확인한다.

## 7. Frontmatter Contract

아래는 신규 초안용 기본값이다. 빈 필드가 있는 상태는 발행 PASS가 아니다. 기존 저장소의 스키마를 확인한 뒤 필드를 매핑하며 중복 YAML 키를 만들지 않는다.

```yaml
contentType: investment-analysis
contentQuestion: "이 글이 답할 핵심 질문"
timeSensitive: true
status: draft
trust:
  author: JoyLab Research
  authorPerspective: "실제 분석 관점"
  humanReviewed: false
  reviewedBy: null
  reviewedAt: null
  reviewScope: []
  researchedAt: "2026-10-06"
  updatedAt: "2026-10-06"
  methodology: []
  primarySources: []
  originalValue: []
  counterEvidenceSections: []
  conclusionSection: null
  updateLog:
    - date: "2026-10-06"
      change: "초안 작성"
publishing:
  trustGate: pending
  originalityGate: pending
  similarityGate: pending
  siteGate: pending
  checkedBy: null
  checkedAt: null
```

출처 항목은 `id / title / publisher / url / publishedAt / accessedAt / supports`를 기록한다. `publishedAt`은 알 수 없으면 null로 두며 추정하지 않는다. `supports`는 실제 주장 ID 목록이다.

고유 가치 항목은 `kind / sectionId / description`을 기록한다. 종류는 analysis, calculation, comparison, framework, scenario, checklist, decision-tree, field-case, data-reconstruction, template 중 실제 결과에 맞게 선택한다. 종류 이름만 기록해 통과시키지 않는다.

검토 완료 시 `humanReviewed`를 true로 바꾸고 검토자·날짜·범위를 함께 채운다. `updatedAt`은 실제 변경일이며 `researchedAt`과 자동으로 함께 갱신하지 않는다.

## 8. Publishing Gate

### Gate A. 정책과 사실

정책 위반, 허위 검토 표시, 조작된 수치·출처, 권리 문제가 확인되면 BLOCK한다. 미확인 핵심 주장 때문에 결론을 검증할 수 없으면 REVIEW로 보류한다. 사이트에 접근할 수 없거나 주요 페이지가 미완성이면 재심사 준비 완료로 표시하지 않는다.

### Gate B. Trust

7개 항목은 작성자 / 기준일 / 조사 방법 / 출처 / 고유 가치 / 반대 근거 / 결론이다. 투자형은 7/7 PASS. 다른 유형은 적용되는 항목을 모두 통과해야 한다.

비시의적 글의 기준일과 순수 정의 글의 반대 근거는 근거를 적고 N/A 처리할 수 있다. 오해·적용 범위로 대체하는 방식이 우선이다. 적용되는 항목 하나를 빠뜨린 뒤 6/7로 통과시키는 방식은 폐기한다. 업데이트 이력은 시간 민감 글의 별도 필수 항목이다.

### Gate C. 고유 가치

- 제목이 약속한 질문에 본문이 답한다.
- 외부 자료에서 가져온 내용과 JoyLab의 해석이 구분된다.
- 자체 결과물 하나 이상이 독자의 이해·판단·실행을 개선한다.
- 계산·비교·템플릿의 가정과 사용 조건을 확인할 수 있다.

요약 재배열, 문장 바꾸기, 장식 이미지 추가만으로 PASS하지 않는다.

### Gate D. Similarity

제목의 실질적 약속 / H2 흐름 / 도입 논리 / CTA / 결론 논리 / 시각 자료의 정보 구성을 비교한다. 공통 Trust UI·출처 제목·법적 고지·유형의 필수 분석 요소는 제외한다.

3개 이상 실질적으로 유사하면 REVIEW, 5개 이상이면 내부 자동 발행 BLOCK으로 보류한다. 이는 Google 기준이 아닌 JoyLab 검토 트리거다. 표현만 바꿔 해제하지 않고 질문·근거·독자 효용의 차이를 검토자가 기록한다. 같은 질문에 같은 답을 주는 글은 일치 항목 수와 무관하게 통합 검토한다. 퍼센트 유사도는 실제 비교 방법 없이 표시하지 않는다.

### Gate E. 공개 화면

글·이미지·표·출처 링크·내부 링크가 실제 배포 페이지에서 정상 작동해야 한다. 소스 코드나 메타데이터의 PASS만으로 완료하지 않는다. REVIEW와 BLOCK 상태는 신규 공개를 보류한다.

## 9. 기존 글 Migration

기존 글 수는 현재 사이트·저장소에서 확인한다. 123개는 기존 계획 수치이며 현재 전수검사 결과로 취급하지 않는다.

| 판정 | 조건 | 조치 |
| --- | --- | --- |
| KEEP | 질문·근거·고유 가치·화면 품질 충분 | 필요한 최신성 확인 |
| ENHANCE | 본문은 유용하나 신뢰 근거·자료 부족 | 실제 출처·분석·기준일 보강 |
| REWRITE | 질문에 답하지 못하거나 구조·논리 부족 | 본문 재설계 |
| MERGE | 같은 질문과 결론의 중복 | 대표 글로 고유 내용 통합 |
| ARCHIVE | 독립 가치 부족·개선 우선순위 낮음 | 공개 유지·비공개·삭제 여부 별도 결정 |

`index / noindex`는 검색 설정이고 ARCHIVE는 편집 상태다. 별도 관리한다. noindex만으로 저가치 콘텐츠나 정책 문제가 해결됐다고 보지 않는다. 공개 페이지의 역할·내용·광고 상태까지 확인한다.

통합 시 대표 URL, 보존할 내용, 리디렉션 대상, 내부 링크·사이트맵 변경을 기록한다. 관련 없는 글로 일괄 리디렉션하지 않는다.

### 개선 우선순위

- P0: 정책 문제·허위 정보·출처 조작·공개 기능 장애
- P1: 홈·주요 메뉴에 노출되는 핵심 글, 중복 묶음, 시효가 지난 핵심 데이터
- P2: 보조 설명 글과 읽기 구조 개선

첫 작업 묶음은 대표 글 5~10편을 시작점으로 선정할 수 있다. 이는 작업 규모 제안이며 승인에 필요한 글 수가 아니다. 이후 전체 공개 콘텐츠의 미해결 항목을 점검한다.

감사표에는 URL / 유형 / 핵심 질문 / 고유 가치 / 출처 상태 / 시의성 / 판정 / 우선순위 / 작업 / 담당 / 완료 근거를 기록한다. 아직 검사하지 않은 글에 PASS를 부여하지 않는다.

## 10. Site Gate

| 영역 | 완료 기준 | 성격 |
| --- | --- | --- |
| 홈·탐색 | 사이트 주제와 주요 자료가 명확하고 메뉴가 작동 | 공식 준비 안내 기반 |
| 콘텐츠 목록 | 빈 카테고리·중복 탐색·미완성 화면 개선 | 내부 사용성 기준 |
| 작성 주체 | 소개·작성 관점이 실제 운영과 일치 | 내부 신뢰 기준 |
| 문의·정정 | 사용 가능한 연락·오류 제보 경로 | 내부 운영 기준 |
| 개인정보 안내 | 실제 데이터·쿠키·광고 처리에 맞는 고지 및 해당 정책 준수 | 관련 공식 정책 적용 |
| 권리·광고 | 복제·이미지 권리·광고 오인 유도 등의 관련 정책 문제 해결 | 공식 정책 적용 |
| 모바일 | 본문·표·메뉴·버튼이 읽히고 동작 | 내부 사용성 기준 |
| 접근 | 심사 대상 공개 페이지와 주요 링크 정상 | 내부 검증 기준 |

소개 페이지나 문의 페이지 하나를 만든 것만으로 승인 준비 완료를 선언하지 않는다. ads.txt·광고 코드·계정 연결은 해당 계정의 실제 안내에 따라 확인하며, 코드 설치와 승인 결과를 구분한다.

## 11. 승인 준비 실행 순서

1. 심사 메시지를 원문 그대로 기록하고 항목별 조치표를 만든다. 메시지가 확인되지 않았다면 거절 사유를 추정해 확정하지 않는다.
2. 공개 URL 목록을 확보하고 유형·중복·신뢰·시의성·사용성을 분류한다.
3. P0를 먼저 해결하고 핵심 글 보강·중복 통합을 진행한다.
4. 홈과 주요 카테고리가 개선된 대표 자료로 연결되도록 정리한다.
5. 소개·개인정보 안내·연락 경로·모바일·링크를 점검한다.
6. 배포 URL에서 변경 결과를 확인하고 검증 기록을 남긴다.
7. 재심사 조건 충족 여부를 확인한 뒤 계정에 표시된 절차로 요청한다. 고정된 대기일을 임의로 만들지 않는다.

## 12. 모니터링과 완료 기준

| 지표 | 정의 | 내부 목표 |
| --- | --- | --- |
| 실제 승인 결과 | 애드센스 계정의 사이트 심사 상태 | 승인 확인 |
| 공개 콘텐츠 감사율 | 검사 완료 URL / 대상 공개 콘텐츠 URL | 재심사 전 100% |
| P0 잔여 | 미해결 정책·사실·기능 문제 | 0건 |
| 핵심 글 Trust 통과율 | 통과 핵심 글 / 선정 핵심 글 | 100% |
| 출처 검증률 | 확인 완료 핵심 외부 주장 / 해당 주장 | 100% |
| 공개 글의 고유 가치 확인율 | 실질적 기여 확인 글 / 공개 글 | 100% |
| 주요 경로 오류 | 홈·메뉴·대표 글의 미해결 오류 | 0건 |

검사 대상을 좁혀 지표만 높이지 않는다. 검증하지 않은 URL이나 주장도 분모에서 임의로 빼지 않는다.

상태는 `AUDIT_PENDING → REMEDIATING → READY_FOR_REVIEW → SUBMITTED → APPROVED / NEEDS_WORK`로 관리한다. READY_FOR_REVIEW는 내부 준비 상태다. 실제 계정 증거 없이 APPROVED로 바꾸지 않는다.

## 13. 최종 운영 선언

JoyLab은 애드센스 승인을 목표로, 조사·비교·판단·실행 도구가 담긴 고유 콘텐츠를 구축한다. 신뢰 기준은 공통으로 적용하고 본문은 질문에 맞춰 구성한다. 기존 핵심 자료의 보강과 중복 정리를 우선하며, 공개 사이트 검증 이후 재심사를 진행한다.
