Codex를 처음 배울 때 가장 어려운 질문은 “기능이 뭐지?”가 아닙니다.

**“그래서 내 업무에서 뭘 맡길 수 있지?”**가 더 어렵습니다.

1부에서는 Codex를 시작하기 위한 기본 세팅, Goal mode, Skills, Plugins, Computer Use, 프로젝트·터미널 활용을 6단계로 정리했습니다.

→ [1부｜코딩 몰라도 시작하는 ChatGPT Codex 활용법 6단계](/articles/codex-guide-6-steps-2026)

이번 글은 기능 설명보다 **실제 업무 단위**에 집중합니다. 코드를 몰라도 시작할 수 있고, 한 번 성공하면 Skill로 만들어 반복할 수 있는 작업 10가지를 선정했습니다.

## 먼저 기억할 원칙｜자동화는 ‘업무 전체’보다 ‘반복 가능한 단위’부터

처음부터 “내 일을 전부 자동화해줘”라고 하면 범위가 너무 넓습니다.

더 안정적인 방식은 다음 순서입니다.

1. 반복 빈도가 높은 작업을 고릅니다.
2. 입력 자료를 명확히 합니다.
3. 결과물 형식을 고정합니다.
4. 완료 기준을 숫자나 체크리스트로 만듭니다.
5. 성공한 뒤 Skill과 Plugin을 붙입니다.

이 기준으로 아래 10가지를 보면 됩니다.

## 1. 회의자료 1페이지 요약

### 이런 사람에게 적합
매주 비슷한 형식의 회의자료를 만드는 사람.

### 입력
- 지난주 보고서
- 이번 주 실적 데이터
- 이슈 메모
- 기존 1페이지 템플릿

### Codex에게 맡길 일
자료를 읽고 핵심 숫자, 문제, 원인, 다음 액션을 같은 형식으로 정리합니다.

### 완료 기준
- 핵심 KPI 5개 이내
- 문제 TOP3
- 다음 액션 TOP3
- 출처 파일 표시
- 1페이지 분량

**추천 조합:** 프로젝트 폴더 + Skill

## 2. 여러 문서 비교 후 변경사항 추출

정책 문서, 매뉴얼, 계약서, 제품 가이드처럼 버전이 자주 바뀌는 업무에 유용합니다.

예를 들어 V1과 V2 문서를 넣고 다음처럼 요청할 수 있습니다.

> 변경된 조항만 뽑고, 추가·삭제·수정으로 구분해 표로 정리해줘. 실무 영향이 있는 항목에는 ‘조치 필요’를 표시해줘.

### 완료 기준
- 변경된 항목만 표시
- 원문 위치 포함
- 영향도 구분
- 확인이 필요한 항목 별도 표시

**추천 조합:** 프로젝트 폴더 + 문서 Skill

## 3. Gmail → 업무 브리핑 자동화

플러그인을 연결하면 받은 메일 중 필요한 내용만 추려 브리핑으로 만들 수 있습니다.

예:

- 오늘 들어온 프로젝트 관련 메일 찾기
- 결정사항 분리
- 요청사항과 담당자 추출
- 미회신 항목 표시
- 한 페이지 브리핑 생성

메일 전체를 읽는 시간을 줄이는 데 특히 효과적입니다.

**추천 조합:** Gmail Plugin + Briefing Skill

## 4. Drive 자료 → 보고서 초안

Google Drive에 흩어진 회의록, 시트, 기획서, 참고자료를 한 번에 묶어 보고서 초안을 만들 수 있습니다.

여기서 중요한 것은 “요약해줘”가 아니라 **보고서 구조를 먼저 고정하는 것**입니다.

예:

```text
1. Executive Summary
2. 현재 상태
3. 핵심 문제
4. 원인
5. 선택지
6. 권고 액션
7. 근거 자료
```

**추천 조합:** Google Drive Plugin + 보고서 Skill

## 5. 웹사이트 문구·SEO 일괄 점검

비개발자에게 의외로 효율이 높은 영역입니다.

Codex에게 사이트 프로젝트를 열게 한 뒤 다음을 맡길 수 있습니다.

- 제목 중복 점검
- 메타 설명 누락 확인
- 깨진 내부링크 탐지
- 오래된 문구 검색
- CTA 일관성 확인
- 모바일 레이아웃 문제 후보 찾기

중요한 것은 한 번에 전부 고치게 하는 것보다 **진단 → 수정 목록 → 승인 → 구현 → 테스트** 순서를 지키는 것입니다.

**추천 조합:** 프로젝트 + Goal mode + QA Skill

## 6. 반복되는 엑셀·CSV 정리

열 이름 통일, 중복 제거, 날짜 형식 정리, 코드 매핑, 누락 데이터 검사처럼 사람이 반복해서 하는 정리 작업을 자동화할 수 있습니다.

### 좋은 자동화 대상
- 매일 같은 열 구조
- 결과 형식이 명확
- 오류 조건을 정의할 수 있음
- 원본을 보존할 수 있음

### 완료 기준 예시
- 원본 파일 수정 금지
- 결과 파일 별도 저장
- 누락값 목록 생성
- 처리 건수와 오류 건수 보고

**추천 조합:** 로컬 폴더 + 데이터 정리 Skill

## 7. 고객 인터뷰·VOC 로그 구조화

상담 기록, 인터뷰 노트, VOC처럼 비정형 텍스트가 쌓이는 조직에서 활용 가치가 큽니다.

Codex에게 다음 구조로 분류하게 할 수 있습니다.

- 문의 유형
- 고객 의도
- 반복 불편
- 원인
- 해결 여부
- 후속 조치
- 개선 아이디어

여러 건을 모으면 단순 요약이 아니라 **패턴 분석용 데이터셋**으로 만들 수 있습니다.

**추천 조합:** 로컬 폴더 + 분류 Skill

## 8. 교육자료·퀴즈 자동 생성

매뉴얼이나 정책 문서를 기준으로 교육자료와 퀴즈 초안을 만들 수 있습니다.

예:

- 초급 5문제
- 중급 5문제
- 상황형 5문제
- 정답과 해설
- 오답이 나오는 이유
- 관련 규정 위치

여기서는 “재미있는 문제”보다 **근거 문서와 정답 일치 여부**가 품질 기준입니다.

**추천 조합:** 지식 폴더 + 교육 Skill

## 9. 웹페이지·간단한 내부 도구 제작

코딩을 몰라도 간단한 대시보드, 입력 폼, 체크리스트, 퀴즈 페이지, 계산기 등은 Codex와 함께 만들 수 있습니다.

핵심은 기술 스택을 먼저 고르는 것이 아니라 기능을 정의하는 것입니다.

예:

```text
사용자는 이름과 점수를 입력한다.
저장 버튼을 누르면 오늘 기록에 추가된다.
점수 80점 미만이면 주의 표시한다.
모바일에서도 한 화면에 보이게 한다.
데이터는 로컬에 저장한다.
```

이렇게 요구사항을 행동 단위로 쓰면 구현 정확도가 높아집니다.

**추천 조합:** Goal mode + 프로젝트 + 브라우저 QA

## 10. 반복 업무를 Skill로 패키징

마지막 단계는 개별 작업이 아니라 **자동화 자체를 재사용 가능한 자산으로 만드는 것**입니다.

예를 들어 매주 월요일 다음 작업을 반복한다고 가정해보겠습니다.

1. 지난주 자료 읽기
2. KPI 계산
3. 문제 TOP3 선정
4. 리더 코칭 문구 작성
5. 1페이지 보고서 생성

한 번 잘 돌아가는 흐름을 만든 뒤 Skill로 묶으면 다음부터는 입력자료만 바꾸면 됩니다.

이 단계부터 Codex는 단순한 도우미가 아니라 **내 업무 방식이 담긴 실행 시스템**에 가까워집니다.

## 난이도별 추천 시작 순서

### 초급
- 문서 요약
- 문서 비교
- 회의 브리핑
- 교육자료 생성

### 중급
- Gmail·Drive 연결
- CSV 정리
- VOC 구조화
- SEO 점검

### 고급
- 웹사이트 수정
- 내부 도구 제작
- 여러 Plugin을 연결한 반복 Skill

처음에는 **실패해도 되돌리기 쉬운 작업**부터 시작하는 것이 좋습니다.

## JoyLab 자동화 판단 기준

모든 업무를 자동화할 필요는 없습니다.

아래 네 질문 중 3개 이상이 “예”라면 자동화 후보로 볼 수 있습니다.

1. 한 달에 두 번 이상 반복되는가?
2. 입력과 출력 형식이 어느 정도 고정돼 있는가?
3. 사람이 하는 과정에서 복사·정리·비교가 많은가?
4. 완료 여부를 체크리스트로 판정할 수 있는가?

반대로 예외 판단이 많고, 고객·조직에 큰 영향을 주며, 잘못됐을 때 복구가 어려운 의사결정은 사람의 검토를 마지막 단계에 남기는 편이 안전합니다.

## 바로 복사해서 쓰는 자동화 발굴 프롬프트

```text
내가 반복하는 업무를 자동화 후보로 분석해줘.

각 업무를 아래 기준으로 평가해.
- 반복 빈도
- 입력자료의 규칙성
- 결과물의 규칙성
- 오류 발생 시 위험도
- 사람이 반드시 판단해야 하는 부분

그 다음 자동화하기 좋은 순서대로 TOP5를 제안해줘.

각 후보마다
1. 자동화 범위
2. 필요한 입력
3. 완료 기준
4. 추천 Codex 기능
5. 사람이 최종 확인할 부분
을 작성해줘.
```

Codex의 가치가 가장 크게 나타나는 지점은 화려한 데모보다 **매주 반복하는 평범한 업무를 줄이는 순간**입니다.

작은 작업 하나를 고르고, 완료 기준을 만들고, 한 번 성공한 흐름을 Skill로 묶으세요.

자동화의 시작점은 AI 기능이 아니라 **반복되는 내 업무를 정확히 정의하는 것**입니다.
