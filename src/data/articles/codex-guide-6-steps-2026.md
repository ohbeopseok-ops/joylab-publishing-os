ChatGPT를 쓰면서 **Codex를 한 번도 써보지 않았다면, 구독에서 활용할 수 있는 작업 범위를 상당 부분 놓치고 있을 수 있습니다.**

Codex는 더 이상 개발자만의 코딩 도구로 보기 어렵습니다. OpenAI는 2026년 Codex를 여러 에이전트와 장기 작업을 관리하는 데스크톱 작업 환경으로 확장했고, 비개발자도 분석·문서·대시보드·내부 앱 제작 등에 활용하고 있다고 설명합니다.

중요한 건 코드를 아는지가 아니라 **“어떤 결과를 만들고 싶은지, 어떤 자료를 참고해야 하는지, 완료 기준이 무엇인지”를 명확하게 주는 것**입니다.

이 글에서는 처음 시작하는 사람 기준으로 Codex 활용을 6단계로 정리합니다.

> **JoyLab 한 줄 정리**  
> ChatGPT가 ‘생각하고 답하는 도구’에 가깝다면, Codex는 **파일·프로젝트·도구를 붙여 실제 결과물까지 만들어가는 작업 환경**으로 보면 이해가 쉽습니다.

## 1. 기본 세팅｜프로젝트 폴더부터 잡는다

Codex를 처음 열었다면 가장 먼저 할 일은 모델을 고민하는 것이 아니라 **작업 공간을 만드는 것**입니다.


### 시작 순서

1. ChatGPT 데스크톱 앱에서 **Codex**로 전환합니다.
2. 작업할 **프로젝트**를 만듭니다.
3. 로컬 폴더를 연결하고 필요한 파일 접근 권한만 허용합니다.
4. 프로젝트에서 반복해서 지켜야 할 원칙이 있다면 지침에 적어둡니다.
5. 파일 삭제·외부 전송·시스템 변경처럼 되돌리기 어려운 작업은 승인 단계를 유지합니다.

로컬 폴더를 프로젝트와 연결하면 Codex가 그 안의 문서와 소스 파일을 읽고, 필요한 경우 파일을 수정하거나 새 결과물을 만들 수 있습니다.

여기서 중요한 점은 **무조건 자동 승인으로 바꾸는 것보다 작업 위험도에 따라 승인 범위를 정하는 것**입니다. 웹사이트 문구 수정과 폴더 전체 삭제는 같은 수준의 권한으로 다뤄서는 안 됩니다.

## 2. 작업 모드｜즉시 실행과 목표 중심 작업을 구분한다


Codex를 잘 쓰려면 모든 요청을 같은 방식으로 던지지 않는 것이 좋습니다.

### 일반 작업
짧은 질문, 파일 한두 개 수정, 문구 교체처럼 범위가 작고 완료 조건이 명확한 작업에 적합합니다.

### 목표 중심 작업
OpenAI의 **Goal mode**는 결과와 성공 기준을 정해주면 Codex가 그 목표를 향해 여러 단계를 이어서 작업하는 방식입니다.

### 계획이 필요한 작업
처음 만드는 사이트나 자동화처럼 방향이 아직 정리되지 않았다면 곧바로 구현시키기보다 먼저 구조를 설계하게 합니다.

## 3. 스킬｜반복 작업을 재사용 가능한 워크플로로 만든다


**Skill**은 자주 하는 작업의 지침, 예시, 코드, 실행 순서를 재사용할 수 있게 묶는 기능입니다.

활용 범위는 영상, 보고서, PPT, 엑셀, 블로그 발행, 웹사이트 QA, 리서치 수집·요약·검증 등으로 넓힐 수 있습니다.

특히 OpenAI는 **Record & Replay**를 통해 반복 작업을 한 번 시연한 뒤 재사용 가능한 Skill로 만드는 흐름도 제공하고 있습니다. 다만 Skill·Record & Replay의 제공 범위는 플랜, 운영체제, 워크스페이스 설정에 따라 달라질 수 있습니다.

## 4. 플러그인｜Codex를 외부 업무 도구와 연결한다


플러그인은 Codex의 작업 범위를 Gmail, Google Drive, GitHub, Calendar, Notion 같은 외부 시스템으로 확장합니다.

지원되는 Codex 작업 화면에서는 **Sources → Use plugins**에서 설치된 플러그인을 선택할 수 있습니다.

여기에 Skill까지 결합하면 단순 연결이 아니라 **반복 가능한 업무 시스템**이 됩니다.

## 5. Computer Use｜화면을 직접 보고 앱을 조작한다

Computer Use는 Codex가 그래픽 화면을 보고 클릭·입력하면서 작업하는 기능입니다.

OpenAI는 현재 지원 지역의 macOS와 Windows 데스크톱 앱에서 Computer Use를 제공하고 있습니다.

활용 예시는 브라우저 반복 입력, 문서 프로그램 조작, 디자인 도구 수정, 앱 설정 변경, GUI에서만 재현되는 오류 확인 등입니다.

다만 Computer Use는 파일 기반 자동화나 API 연동보다 느릴 수 있고 화면 변화에 영향을 받습니다. **대량 반복 작업은 먼저 파일·API·플러그인 방식이 가능한지 확인하고, GUI 작업이 꼭 필요한 경우에 사용하는 편이 효율적**입니다.

## 6. 사이드 패널·터미널｜다른 도구와 함께 쓴다


Codex 프로젝트에서는 결과를 대화창 하나에만 가두지 않고, 프로젝트 파일·터미널·개발 도구와 연결해 작업할 수 있습니다.

비개발자에게 터미널은 낯설 수 있지만 직접 명령어를 외울 필요는 없습니다. 핵심은 여러 도구를 무조건 많이 쓰는 것이 아니라 **하나의 주 작업 흐름을 먼저 안정화하고, 다른 도구는 검토·보완·비교가 필요할 때만 붙이는 것**입니다.

## 비개발자라면 이렇게 시작하면 된다

1. 작은 작업 하나를 고릅니다.
2. 좋은 결과의 기준을 적습니다.
3. 실제 예시를 줍니다.
4. 한 번 성공한 흐름을 Skill로 만듭니다.
5. 외부 데이터가 필요하면 Plugin을 붙입니다.
6. 마지막에 Computer Use를 검토합니다.

## Codex에서 가장 중요한 것은 프롬프트보다 ‘완료 기준’이다

비개발자가 Codex를 어려워하는 가장 큰 이유는 코딩을 몰라서가 아니라, **완료의 기준이 없는 요청**을 주기 때문입니다.

아래 다섯 가지만 고정해도 결과가 크게 달라집니다.

1. **목표** — 무엇을 만들 것인가
2. **범위** — 어디까지 수정할 것인가
3. **참고 자료** — 무엇을 기준으로 볼 것인가
4. **완료 조건** — 무엇이 되면 끝인가
5. **검증 방식** — 결과가 맞는지 어떻게 확인할 것인가

## 팩트 체크｜원문에서 보정한 부분

- Codex는 Windows와 macOS 데스크톱 환경에서 사용할 수 있습니다.
- Goal mode는 결과와 성공 기준을 중심으로 장기 작업을 이어가는 기능입니다.
- Skills와 Plugins는 재사용 워크플로와 외부 시스템 연결을 지원하지만, **플랜·워크스페이스·관리자 설정에 따라 제공 범위가 달라질 수 있습니다.**
- Computer Use는 Windows/macOS GUI를 보고 조작할 수 있지만, 지원 지역과 권한 설정에 영향을 받습니다.
- “Codex를 안 쓰면 구독료의 50%를 못 쓴다”는 수치형 표현은 공식적인 사용 가치 측정치가 아니므로 이 글에서는 사용하지 않았습니다.

**JoyLab Conclusion**

Codex를 잘 쓰는 사람과 못 쓰는 사람의 차이는 코딩 실력보다 **업무를 구조화하는 능력**에서 더 크게 벌어집니다.

작은 작업을 하나 고르고, 완료 기준을 정하고, 반복되는 흐름을 Skill로 만들고, 필요한 곳에 Plugin과 Computer Use를 붙이세요.

그 순간부터 Codex는 ‘코딩을 해주는 도구’가 아니라 **내 업무를 실행하는 작업 시스템**으로 바뀝니다.
