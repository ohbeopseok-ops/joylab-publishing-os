AI 브라우저 **Aside가 Windows 버전을 정식 출시했다.**

맥 중심으로 사용하던 브라우저 에이전트 경험이 이제 Windows 사용자까지 확장됐다는 점에서 의미가 크다. 특히 국내 기업과 실무 환경은 여전히 Windows 비중이 높은 만큼, 이번 출시는 단순한 운영체제 지원 확대보다 **AI 에이전트가 실제 업무 PC 안으로 들어오는 계기**에 가깝다.

Aside 공식 사이트는 현재 제품 다운로드를 제공하고 있으며, Aside를 단순 검색형 브라우저가 아니라 **로그인된 웹사이트에서 사용자를 대신해 실제 작업을 수행하는 브라우저 에이전트**로 설명한다.

## Research Brief

- Aside for Windows가 출시되며 사용 범위가 Mac 중심에서 Windows까지 확대됐다.
- 핵심은 검색 기능이 아니라 로그인된 웹서비스 안에서 실제 작업을 수행하는 브라우저 에이전트 구조다.
- 로컬 우선 메모리, 자격증명 보호, 민감 작업 승인 구조가 실무형 AI 브라우저의 차별점이다.
- Windows 확장은 기업·운영·리서치 환경에서 AI 브라우저 도입 장벽을 크게 낮출 수 있다.

## Key Takeaways

1. **AI 브라우저 경쟁의 기준이 검색에서 실행으로 이동하고 있다.**
2. **Windows 지원은 실제 업무 현장 확산에 훨씬 중요한 변수다.**
3. **브라우저 안에서 실행되는 에이전트는 기존 SaaS 연동 방식과 다른 생산성 구조를 만든다.**

## JoyLab AI Productivity Framework

**Problem → Capability → Workflow Fit → Human Control → Measurement → Risk → Scenario → Action**

## 1. PROBLEM | 기존 AI 브라우저의 한계는 무엇이었나

기존 AI 브라우저의 상당수는 검색, 요약, 질의응답에 강했다.

하지만 실제 업무에서는 문제가 달랐다.

- 로그인된 웹사이트에서 직접 작업해야 한다.
- 여러 사이트를 오가며 정보를 모아야 한다.
- 폼 입력, 문서 다운로드, 메시지 작성 같은 반복 작업이 필요하다.
- 중간에 승인이나 권한 확인이 필요하다.
- 작업 결과가 남아야 한다.

즉, 사용자가 원하는 것은 “답을 알려주는 브라우저”보다 **업무를 끝내주는 브라우저**다.

Aside는 공식적으로 자신을 “browser built to do real work”라고 정의한다. 이메일, 대시보드, 내부 도구처럼 사용자가 이미 로그인한 웹서비스를 직접 이용하는 구조가 핵심이다.

## 2. CAPABILITY | Aside는 무엇이 다른가

Aside의 차별점은 크게 네 가지다.

### 로그인된 웹사이트를 직접 사용

별도의 API 연동이 없어도 사용자가 이미 로그인한 웹사이트를 브라우저 안에서 직접 이용한다.

이 구조는 업무 자동화의 범위를 넓힌다. API가 없는 내부 시스템이나 웹 기반 관리도구도 브라우저에서 접근 가능하다면 작업 대상이 될 수 있기 때문이다.

### 브라우징 기록 기반 메모리

Aside는 사용자가 어떤 사이트에서 어떤 일을 하는지 기억해 반복 설명을 줄이는 방향을 택하고 있다.

공식 설명에 따르면 메모리는 로컬 중심으로 동작하며, 사용자가 반복적으로 수행하는 업무 맥락을 이어받는 것이 목표다.

### 자격증명 보호

AI 에이전트가 로그인 정보 자체를 읽는 방식이 아니라 자동완성으로 자격증명을 입력하고, 모델에는 비밀번호를 직접 노출하지 않는 구조를 강조한다.

### 민감 작업은 사람 승인

결제, 게시, 메시지 전송처럼 결과가 외부에 영향을 주는 작업은 사용자 승인을 기다리는 구조를 둔다.

이는 JoyLab이 업무 자동화에서 강조해온 **Human Approval** 원칙과 정확히 맞닿아 있다.

## 3. WORKFLOW FIT | Windows 출시는 왜 중요한가

Mac 지원만으로도 제품의 가능성은 보여줄 수 있다.

하지만 실제 조직 확산은 Windows 지원 여부가 훨씬 중요하다.

특히 다음 환경에서 의미가 크다.

- 기업 사무직 PC
- 고객센터 운영 PC
- 리서치 조직
- 개발·QA 조직
- 재무·운영·영업 관리 환경

국내 기업은 브라우저 기반 사내 시스템과 Windows PC 조합이 여전히 일반적이다.

따라서 Windows 지원은 Aside가 개인 생산성 도구에서 **조직 업무 자동화 도구로 확장될 수 있는 조건**을 만든다.

## 4. TECHNOLOGY | Aside는 왜 코딩 에이전트처럼 동작하나

Aside의 기술적 접근도 흥미롭다.

공식 연구 글에 따르면 Aside는 브라우저 제어를 위해 Playwright 계열 인터페이스와 JS 실행 환경을 적극 활용한다. 개발팀은 모델이 이미 코드와 Playwright 문법에 익숙하다는 점을 활용해 브라우저 행동을 코드 형태로 표현하는 방식을 선택했다.

이 접근의 핵심은 단순하다.

**AI에게 새로운 조작 언어를 가르치기보다, 이미 학습한 표현 방식을 그대로 쓰게 한다.**

또한 접근성 트리 기반 화면 정보를 압축해 에이전트에 전달하고, DOM 제어가 어려운 상황에서는 화면 기반 Computer Use 방식으로 전환한다.

결국 Aside는 “AI가 붙은 브라우저”라기보다 **브라우저를 사용할 수 있는 코딩 에이전트**에 가깝다.

## 5. HUMAN CONTROL | 실무에서는 자동 실행보다 통제가 중요하다

브라우저 에이전트가 강력해질수록 통제 구조가 중요해진다.

Aside 약관도 AI 출력과 자동화 결과가 잘못되거나 불완전할 수 있다고 명시하고 있으며, 메시지·구매·결제·예약·계정 변경·게시 같은 고위험 작업은 사용자가 검토해야 한다고 안내한다.

JoyLab 관점에서는 다음처럼 구분하는 것이 안전하다.

| 위험도 | 예시 | 권장 방식 |
| --- | --- | --- |
| Low | 검색, 자료 수집, 요약 | 자동 실행 |
| Medium | 초안 작성, 비교표 생성 | 결과 검수 |
| High | 고객 메시지, 게시, 결제 | 실행 전 승인 |
| Critical | 권한 변경, 대량 삭제, 금융 실행 | 이중 승인 또는 자동화 제외 |

AI 브라우저의 핵심 경쟁력은 “얼마나 많이 자동화하는가”가 아니라 **어디까지 자동화하고 어디서 사람에게 넘기는가**에서 결정될 가능성이 높다.

## 6. RESEARCH | 리서치 업무에는 어떻게 쓸 수 있나

Aside는 공식적으로 Researchers용 활용 사례도 제시하고 있다.

예를 들면 다음과 같다.

- 여러 사이트에서 자료 수집
- 주장 검증
- 가격 페이지 캡처
- PDF 필드 추출
- 출처 근거 기록

JoyLab 워크플로에 연결하면 더 구체적이다.

**키워드 입력 → 공식 자료 탐색 → 기사 교차검증 → 핵심 수치 추출 → 출처 기록 → 초안 생성 → 사람 검수 → 발행**

이 과정에서 사람이 반복적으로 하던 브라우저 이동과 자료 정리를 에이전트가 맡는다면, AI 도입 효과는 단순 글쓰기 속도보다 **리서치 준비시간 절감**에서 더 크게 나타날 수 있다.

## 7. RISK | 아직 확인해야 할 부분

Windows 출시 자체가 제품 완성도를 보장하는 것은 아니다.

특히 확인할 부분은 네 가지다.

### 안정성

Mac에서 잘 작동하던 자동화가 Windows 환경에서도 동일하게 안정적으로 실행되는지 확인이 필요하다.

### 사이트 호환성

보안이 강한 기업 사이트, 인증서 기반 사이트, 특수 입력창 등은 실제 사용 과정에서 차이가 생길 수 있다.

### 개인정보와 기업 데이터

Aside는 로컬 우선 구조를 강조하지만, 일부 AI 기능은 외부 모델 제공자나 서버 처리가 필요할 수 있다. 기업 환경에서는 사내 보안정책과 데이터 처리 범위를 반드시 확인해야 한다.

### 에이전트 오류

브라우저 에이전트는 웹페이지의 잘못된 지시나 프롬프트 인젝션에 영향을 받을 수 있다. 공식 약관도 이런 위험을 완전히 차단할 수 없다고 명시한다.

## 8. SCENARIO | Aside가 성공할 조건

### Success

Windows 안정성이 확보되고, 반복 업무에서 실제 완료율이 높으며, 승인·보안 구조가 신뢰를 얻는 경우다.

### Partial

리서치와 자료수집에는 강하지만 기업 내부 시스템과 보안 환경에서 사용 범위가 제한되는 경우다.

### Failure

AI 브라우저가 검색과 데모 수준을 넘어 실제 반복 업무를 안정적으로 완료하지 못한다면 기존 Chrome + ChatGPT 조합과 차별화가 약해질 수 있다.

## 9. ACTION | JoyLab은 어떻게 테스트하면 좋은가

Aside for Windows는 기능 목록보다 실제 업무 한 건을 기준으로 평가해야 한다.

JoyLab에서는 아래 세 가지 테스트가 적합하다.

### Test 1. 리서치 수집

하나의 투자 또는 AI 키워드를 주고 공식자료 3개, 보조자료 5개를 수집하게 한다.

측정:

- 완료시간
- 출처 정확도
- 중복률
- 사람 수정 횟수

### Test 2. 반복 운영 업무

로그인된 웹도구에서 동일한 작업을 10회 반복한다.

측정:

- 성공률
- 중단 횟수
- 승인 요청 횟수
- 복구 가능 여부

### Test 3. 발행 직전 워크플로

자료 수집 → 초안 → 링크 검증 → 게시 직전까지 실행한다.

실제 게시 버튼은 Human Approval으로 남겨둔다.

이 세 가지를 통과하면 Aside는 단순 체험용 AI 브라우저가 아니라 **JoyLab Research OS의 실행 레이어 후보**로 평가할 수 있다.

## JoyLab 판단

이번 Windows 출시는 기능 하나가 추가된 사건이 아니다.

**AI 에이전트가 ‘웹에서 답하는 도구’에서 ‘업무 PC 안에서 실행하는 도구’로 이동하는 신호**다.

특히 Windows까지 지원되기 시작하면 브라우저 에이전트의 경쟁 상대는 다른 AI 브라우저만이 아니다.

RPA, SaaS 자동화, 브라우저 확장 프로그램, 일부 백오피스 업무까지 경쟁 범위가 넓어진다.

JoyLab이 볼 핵심 지표도 명확하다.

**Answer Quality가 아니라 Task Completion Rate다.**

실제 업무를 얼마나 정확하게 끝내는지가 앞으로 AI 브라우저의 진짜 성능 기준이 될 가능성이 높다.
