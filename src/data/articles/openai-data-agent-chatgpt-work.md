회사에서 이런 질문을 던져본 적이 있을 겁니다.

> 지난주 매출은 왜 떨어졌지?

질문은 한 줄인데 답을 얻는 과정은 길었습니다. 데이터팀에 요청하고, SQL을 만들고, 엑셀을 내려받고, BI 화면을 확인하고, 숫자 정의가 맞는지 다시 검증한 뒤에야 보고가 올라옵니다.

OpenAI가 이 흐름을 바꾸려는 제품을 공개했습니다.

2026년 9월 10일 OpenAI는 **ChatGPT Work의 Data agent**를 발표했습니다. 회사 데이터를 연결해 자연어로 질문하면 관련 데이터를 조사하고, 변화의 원인을 분석하고, 인터랙티브 대시보드까지 만들 수 있도록 설계된 에이전트입니다.

이번 발표에서 더 중요한 변화는 "AI가 차트를 그린다"는 사실이 아닙니다.

**기업 데이터의 인터페이스가 SQL과 대시보드에서 질문으로 이동하기 시작했다는 점**입니다.

## 1. FACT｜OpenAI가 무엇을 공개했나

OpenAI 공식 발표에 따르면 Data agent는 ChatGPT Work에서 기업 데이터를 활용해 비즈니스 질문을 조사하는 에이전트입니다.

사용자는 예를 들어 이렇게 질문할 수 있습니다.

- 지난주 활성 사용자가 왜 감소했는가
- 이번 분기 매출과 지난 분기의 차이는 어디서 발생했는가
- 고객 유지율이 떨어진 주요 원인은 무엇인가
- 지역별 세일즈 파이프라인을 대시보드로 만들어달라

중요한 점은 한 번 답하고 끝나는 형태가 아니라는 것입니다.

같은 대화에서 후속 질문을 이어가며 분석 범위를 좁히고, 결과의 근거를 확인하고, 필요한 경우 분석 방향을 다시 수정할 수 있습니다.

OpenAI는 분석 결과를 **편집·공유·새로고침 가능한 인터랙티브 대시보드**로 만들 수 있다고 설명합니다.

출처: [OpenAI — Now everyone can put data to work](https://openai.com/index/put-data-to-work/)

## 2. CONNECTED DATA｜데이터베이스만 보는 에이전트가 아니다

Data agent의 중요한 특징은 연결 범위입니다.

OpenAI가 공개한 예시에는 다음과 같은 데이터 시스템이 포함됩니다.

- Amazon Redshift
- Google BigQuery
- Databricks
- ClickHouse
- MongoDB
- Snowflake
- Datadog
- Google Drive
- Microsoft SharePoint

즉 데이터웨어하우스만 읽는 구조가 아닙니다.

기업의 실제 판단에는 정형 데이터뿐 아니라 문서, 보고서, 정책, 지표 정의 같은 비정형 맥락도 필요합니다. Data agent는 이런 정보까지 같은 분석 흐름 안에 가져오는 것을 목표로 합니다.

기존 데이터 분석이 흔히

**DB → SQL → BI → 문서 확인 → 보고서 작성**

처럼 나뉘었다면, Data agent가 지향하는 흐름은 다음에 가깝습니다.

**질문 → 관련 데이터·문서 탐색 → 분석 → 시각화 → 후속 질문**

데이터 사용자의 출발점이 "어느 테이블을 봐야 하지?"에서 **"무엇을 알고 싶은가?"**로 바뀌는 것입니다.

## 3. SEMANTIC CONTEXT｜진짜 핵심은 회사의 숫자 정의다

같은 단어라도 회사마다 정의가 다릅니다.

예를 들어 "활성 고객"이 어떤 회사에서는 30일 내 로그인 고객일 수 있고, 다른 회사에서는 최근 결제 고객일 수 있습니다. "매출"도 총거래액인지 순매출인지, 환불을 언제 반영하는지에 따라 숫자가 달라집니다.

OpenAI는 Data agent가 조직의 **비즈니스 용어, 지표 정의, 커스텀 계산식, 데이터 간 관계**를 활용할 수 있다고 설명합니다. 이런 맥락은 Databricks Genie Ontology, dbt, GitHub, Snowflake Horizon, 기존 BI 대시보드 같은 신뢰 소스에서 가져올 수 있습니다.

여기서 중요한 역설이 생깁니다.

**AI가 분석을 쉽게 만들수록 데이터 정의는 더 중요해집니다.**

틀린 KPI 정의를 사람이 월 1회 분석하면 월 1회 틀립니다. 하지만 에이전트가 같은 정의를 바탕으로 하루 수십 번 분석하면 잘못된 판단도 더 빠르게 확산될 수 있습니다.

앞으로 데이터 경쟁력은 단순히 데이터를 많이 쌓는 것보다 다음 질문에 얼마나 명확하게 답할 수 있는지가 중요해집니다.

- 우리 회사의 KPI 정의는 무엇인가
- Source of Truth는 어디인가
- 같은 지표가 충돌하면 무엇을 우선하는가
- 누가 어떤 데이터까지 볼 수 있는가
- 계산식 변경은 어떻게 기록되는가

## 4. DASHBOARD｜BI가 없어지는 것이 아니라 인터페이스가 바뀐다

이번 발표를 "ChatGPT가 Power BI를 없앤다"고 해석하면 과합니다.

OpenAI는 오히려 Data agent가 기존 BI 생태계와 함께 작동한다고 설명합니다. Power BI, Tableau, Sigma, ThoughtSpot, Omni, Oracle BI 같은 도구에서 대시보드를 만들고 탐색하는 흐름을 자연어로 지시할 수 있습니다.

따라서 변화는

**ChatGPT vs BI**

보다는

**ChatGPT → BI**

에 가깝습니다.

BI 엔진과 데이터 모델은 남지만, 사람이 메뉴를 찾고 필터를 조정하고 차트를 조립하는 비중은 줄어들 수 있습니다.

JoyLab이 이번 발표에서 가장 크게 보는 문장은 이것입니다.

> **BI의 다음 인터페이스는 대시보드가 아니라 질문일 수 있다.**

## 5. PERMISSION｜AI가 강해질수록 권한 설계가 중요해진다

기업 데이터 에이전트에서 가장 위험한 질문은 "얼마나 똑똑한가"가 아닙니다.

**누가 무엇을 볼 수 있는가**입니다.

OpenAI는 워크스페이스 관리자가 어떤 데이터 연결을 사용할 수 있는지와 어떤 역할이 사용할 수 있는지를 관리할 수 있다고 설명합니다. 쿼리는 연결된 계정이 이미 가진 접근 권한을 따르며, 테이블·행·열 수준의 제한도 적용됩니다.

따라서 실제 기업 도입에서 중요한 것은 최소 세 가지입니다.

### Identity

누가 질문하고 있는가.

### Permission

그 사람에게 어떤 데이터 접근 권한이 있는가.

### Auditability

어떤 데이터와 정의를 근거로 결론을 냈는가.

에이전트가 강력해질수록 이 세 가지가 약하면 오히려 도입 범위를 넓히기 어렵습니다.

## 6. ACTION｜분석과 실행 사이의 거리가 짧아진다

OpenAI는 이번 제품을 "answers, interactive dashboards, and action"으로 설명합니다.

다만 이것을 "Data agent가 회사 시스템을 마음대로 수정한다"는 의미로 받아들이면 안 됩니다.

실제 실행 범위는 연결된 도구가 지원하는 기능, 사용자의 권한, 워크스페이스 정책과 승인 구조에 따라 달라집니다.

그래서 기업 업무에서 더 현실적인 구조는 다음과 같습니다.

**Analyze → Recommend → Permission Check → Human Decision → Approved Action**

예를 들어 세일즈 조직이라면 매출 둔화 원인을 분석하고 위험 고객군을 찾아낸 뒤, 사람이 근거를 확인하고 승인된 도구에서 후속 업무로 연결하는 식입니다.

이 구조는 기존 [**AI 업무자동화 구조**](/articles/ai-workflow-automation)에서 설명한 Model → Tool → Workflow → Human Approval과 맞닿아 있습니다.

## 7. WORK｜가장 먼저 바뀔 것은 반복 운영 보고일 가능성이 크다

Data agent가 가장 먼저 영향을 줄 영역은 거대한 데이터 사이언스 프로젝트보다 **반복되는 운영 분석과 보고**일 가능성이 높습니다.

예를 들어 고객센터 운영이라면 이런 질문을 생각해볼 수 있습니다.

> 이번 주 NPS가 하락한 핵심 원인을 상담 유형별로 찾아줘.

> 팀별 AHT가 증가한 구간과 문의 유형을 비교해줘.

> 신입 상담사의 Auto QA 취약 항목을 공통 패턴으로 묶어줘.

> 지난달보다 반복 문의가 급증한 상품과 원인을 찾아줘.

> 이 결과를 센터장용 주간 운영 대시보드로 정리해줘.

기존에는 데이터 추출 → 엑셀 → 피벗 → 차트 → PPT → 보고라는 과정이 필요했습니다.

Data agent형 구조에서는 이 흐름이

**질문 → 분석 → 검증 → 대시보드 → 의사결정**

으로 압축될 수 있습니다.

하지만 전제가 있습니다.

NPS, AHT, Auto QA, 상담 유형 같은 데이터 정의가 정리돼 있어야 하고, 팀·개인 단위 접근 권한도 정확해야 합니다.

AI가 분석을 대신해주는 순간 오히려 **데이터 운영체계의 품질이 그대로 드러납니다.**

## 8. OpenAI 내부에서도 데이터 에이전트를 쓰고 있다

OpenAI는 이번 발표에서 자사 내부 활용 수준도 공개했습니다.

공식 발표에 따르면 OpenAI 제품팀의 거의 전부와 GTM 조직의 3분의 2 이상이 ChatGPT Work에서 데이터 에이전트를 사용해 회사 데이터를 직접 분석하고 있습니다.

여기서 중요한 것은 모델만 배포한 것이 아니라는 점입니다.

OpenAI 데이터팀은 이를 위해 공통 비즈니스 정의를 만들고, 접근 규칙을 정하고, 민감 데이터에 대한 보호장치를 구축했다고 설명합니다.

즉 "에이전트 하나 설치하면 데이터 민주화가 끝난다"는 이야기가 아닙니다.

**Agent + Semantic Layer + Permission + Governance**가 하나의 시스템으로 움직여야 한다는 것입니다.

## 9. JOYLAB INTERPRETATION｜SQL의 종말보다 더 큰 변화

이번 발표를 보고 "이제 SQL을 배울 필요가 없어졌다"고 말하는 것은 너무 좁은 해석입니다.

SQL과 데이터 모델은 여전히 시스템 내부에서 중요합니다. 다만 비즈니스 사용자가 매번 직접 SQL을 작성하거나 분석가에게 요청해야 하는 비중은 줄어들 수 있습니다.

그 대신 더 가치가 높아지는 역량이 있습니다.

### 질문 설계

무엇을 비교하고 어떤 가설을 확인할 것인가.

### KPI 정의

무엇을 성공과 실패로 볼 것인가.

### 데이터 품질

AI가 참조하는 데이터가 신뢰할 수 있는가.

### 권한과 거버넌스

누가 어떤 분석과 액션을 수행할 수 있는가.

### 실행 설계

분석 결과를 실제 업무 변화로 어떻게 연결할 것인가.

결국 AI 시대의 데이터 경쟁력은 **데이터를 뽑는 능력에서 데이터를 정의하고 운영하는 능력으로 이동**할 가능성이 큽니다.

## 10. SCENARIO｜세 가지 도입 시나리오

### Bull Case｜질문이 실제 업무 인터페이스가 된다

Semantic Layer와 권한 체계가 잘 갖춰진 조직에서는 비개발자도 반복 분석을 직접 수행하고, 대시보드를 만들고, 승인된 후속 액션까지 이어갈 수 있습니다.

데이터팀은 단순 추출 요청을 처리하는 조직에서 **데이터 제품·정의·품질을 설계하는 조직**으로 이동합니다.

### Base Case｜분석 보조도구로 빠르게 확산된다

대시보드 작성과 탐색은 빨라지지만 중요한 경영 판단은 여전히 데이터팀과 현업의 검증을 거칩니다.

초기 도입 단계에서는 이 시나리오가 가장 현실적입니다.

### Bear Case｜데이터 정의가 엉켜 있어 답만 더 빨리 틀린다

같은 KPI에 여러 정의가 존재하고 데이터 접근 권한이 정리돼 있지 않으면 에이전트 도입 효과가 제한됩니다.

AI 성능 문제가 아니라 **Data Foundation 문제**입니다.

## 11. ACTION｜기업은 무엇부터 준비해야 하나

Data agent 같은 제품을 도입하기 전에 모델 비교부터 시작할 필요는 없습니다.

먼저 다음 다섯 가지를 확인하는 편이 낫습니다.

1. 가장 많이 반복되는 비즈니스 질문 TOP 20을 적습니다.
2. 각 질문에 필요한 Source of Truth를 지정합니다.
3. KPI 정의와 계산식을 문서화합니다.
4. 역할별 데이터 접근 권한을 확인합니다.
5. AI 결과를 검증할 기존 보고서나 대시보드를 정합니다.

그다음 하나의 업무를 선택해 테스트합니다.

**질문 → 답 → 근거 확인 → 기존 보고서 비교 → 대시보드 → 의사결정**

이 과정을 반복하면서 정확도와 시간을 함께 측정해야 합니다.

AI 도입의 성과는 시간 절감 하나로 판단하기 어렵습니다. [**AI 도입 ROI 보는 법**](/articles/ai-productivity-roi)에서 설명한 것처럼 Task Completion, Rework, Human Review, 비용까지 함께 보는 편이 좋습니다.

## FAQ

### OpenAI Data agent는 무엇인가요?

ChatGPT Work에서 연결된 회사 데이터와 비즈니스 맥락을 활용해 자연어 질문을 분석하고, 근거를 확인하며, 인터랙티브 대시보드와 보고서를 만들 수 있도록 설계된 Data 플러그인 기반 에이전트입니다.

### SQL을 몰라도 사용할 수 있나요?

비즈니스 사용자는 자연어로 질문할 수 있습니다. 다만 정확한 분석을 위해서는 조직의 데이터 모델, 지표 정의, 권한, Source of Truth가 잘 관리돼 있어야 합니다.

### Power BI나 Tableau를 대체하나요?

반드시 그렇지는 않습니다. OpenAI는 Data agent가 Power BI, Tableau, Sigma, ThoughtSpot 등 기존 BI 도구와 함께 작동하는 구조를 제시하고 있습니다.

### Data agent가 회사 시스템에서 자동으로 행동하나요?

가능한 후속 액션은 연결된 도구의 기능, 사용자의 권한, 워크스페이스 정책과 승인 구조에 따라 달라집니다. 모든 분석이 자동 실행으로 이어지는 구조는 아닙니다.

## 결론｜BI의 다음 인터페이스는 질문이다

OpenAI Data agent의 핵심은 "AI가 대시보드를 만들어준다"가 아닙니다.

**기업 데이터에 접근하는 기본 인터페이스를 질문으로 바꾸려는 시도**입니다.

지금까지는 데이터를 보기 위해 SQL, 엑셀, BI 사용법을 배워야 했습니다. 앞으로는 사용자가 먼저 비즈니스 질문을 던지고, 에이전트가 데이터와 문서, 지표 정의, BI를 연결하는 방식이 더 넓어질 수 있습니다.

하지만 이 변화가 데이터팀을 덜 중요하게 만드는 것은 아닙니다.

오히려 반대입니다.

AI가 데이터를 더 많은 사람에게 개방할수록 **정확한 KPI 정의, Semantic Layer, 권한, 데이터 품질, 거버넌스**의 중요성은 더 커집니다.

JoyLab의 한 줄 해석은 이것입니다.

> **BI의 다음 인터페이스는 대시보드가 아니라 질문이다.**

그리고 그다음 단계는 이미 보입니다.

**Company Data → Question → Analysis → Dashboard → Decision → Approved Action**

이 흐름이 자리 잡으면 AI는 답변 도구를 넘어 기업의 실제 운영 인터페이스로 들어가게 됩니다.

관련해서 실제 업무를 에이전트 구조로 설계하는 방법은 [**AI 업무자동화 구조｜Model → Tool → Workflow → Human Approval**](/articles/ai-workflow-automation)을 함께 읽어보세요. 조직 전체의 AI 운영체계가 궁금하다면 [**AI 생산성 운영모델**](/articles/ai-productivity-operating-model)로 이어집니다.
